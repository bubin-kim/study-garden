## ② 포트폴리오 설명 (공모전·문서용)

**Study Garden — 공부한 시간이 정원이 되는 타이머, 그리고 정원으로 세우는 공부 계획**

- **문제**: 타이머는 "얼마나" 했는지만 남기고 "무엇을, 왜" 했는지는 모른다. 계획 앱은 반대로 차갑고, 못 지킨 날을 벌한다.
- **접근**: 기존 정원 은유를 그대로 확장했다. 핵심 목표 1~3개를 모두 마친 날엔 달성 꽃이 피고, 과목마다 다른 꽃(5종)이 자라며,
  시험까지 남은 날이 정원 위에 적히고, 한 달은 정원 한 장(PNG)으로 정리된다. 알림·페널티·장기 플래너는 의도적으로 뺐다.
- **결과 (실측)**
  - 마일스톤 5개(M1~M5)를 각각 설계 문서 → 사용자 승인 → 구현 → 브라우저 검증 → 승인 게이트로 진행 (`docs/03_study-planner.md`).
  - 순수 함수 골든 테스트 **59개**(`npm test`) — 기대값 표를 사람이 먼저 승인한 뒤 테스트로 옮겼고, 규칙을 일부러 깨뜨린 변형에서
    해당 케이스가 실패하는지 확인.
  - Playwright 시나리오 5개 **139개 검사**, 라이트·다크 모두, 콘솔 에러 0 — 프로덕션 빌드 대상으로도 통과.
  - 하위 호환: 저장 형식 불변. M1~M5 동안 과목 없는 기존 기록은 V1 커밋과 **스크린샷 바이트 동일**을 유지했고,
    마감 후 사용자 요청으로 식물 아트를 풍성하게 개정(나무에도 과목색 꽃).
  - 과목 색 5개: 종끼리 최소 색차 ΔE 34.5 이상, 적록색약 시뮬레이션에서도 ΔE 10.1 이상.
  - 대표 화면: `docs/screenshots/home-light.png`, `goals-light.png`, `summary-export-dark.png`.
- **기술 선택의 이유**
  - 새 라이브러리 0개 — PNG는 화면 SVG를 복제해 계산된 색으로 굳힌 뒤 canvas로. 의존성 없이 정원과 같은 그림이 나온다.
  - 테스트는 Node 내장 `node --test` — 테스트 프레임워크 설치 없이 순수 함수만 검증.
  - 데이터는 계속 localStorage — 새 키 3개만 추가, 기존 키·형식은 불변이라 마이그레이션이 없다.
  - 과목 색은 CSS 토큰(`--sp-0..4`) — 계절이 바뀌어도 과목은 같은 색이어야 알아볼 수 있으므로 계절 팔레트와 분리.

## ③ 1분 소개 대본 (말하기용)

> 공부 타이머는 시간이 끝나면 사라지고, 계획 앱은 왠지 차갑죠. 저는 집중한 시간이 정원의 식물로 자라는 앱, 스터디 가든을 만들었습니다.
> 이번에는 학생에게 꼭 필요한 계획 기능을 더했어요. 오늘의 핵심 목표를 다 이루면 정원에 꽃이 피고, 과목마다 다른 꽃이 자라고,
> 시험까지 남은 날과 한 달을 정리한 이미지를 보여 줍니다.
> 가장 어려웠던 건 과목 꽃의 색이었어요. 색약이 있는 분에게는 두 색이 거의 같아 보인다는 걸 측정으로 찾았고, 후보 세 개를 비교해서 다시 골랐습니다.
> 판정 규칙은 제가 먼저 승인한 정답표로 테스트 59개를 만들어 지켰습니다. 예쁘다는 말보다, 보인다는 증거를 남기는 법을 배웠습니다.

분량: 공백 포함 340자(공백 제외 258자) — 소리 내어 읽으면 1분 안팎(한국어 낭독 분당 약 300~350자 기준). 실제 낭독 시간은 미측정.

## ④ 기술적 배운 점

**1. framer-motion은 SVG에서 `transformOrigin`을 덮어쓴다** (docs/03 M2 기록, `7f74153`)
- 상황: 달성 꽃이 뿌리가 아니라 가운데에서 커졌다.
- 몰랐던 것: `style={{ transformOrigin }}`이 SVG 요소에서는 framer에 의해 `50% 50%`로 덮인다.
- 알게 된 것: DOM을 직접 재서 확인 — `originX`/`originY` + `transformBox: 'fill-box'`로 줘야 한다. 같은 버그가 V1 식물 등장에도 있었다.
- 다음엔: 애니메이션 기준점은 계산된 스타일을 한 번 찍어 보고 넘어간다. 규칙은 CLAUDE.md에 승격.

**2. "보인다"와 "DOM에 있다"는 다르다 — Playwright `isVisible()`은 opacity를 보지 않는다** (SKILL.md Gotchas)
- 상황: M3 시나리오는 전부 통과했는데 스크린샷이 빈 화면이었다.
- 몰랐던 것: 가짜 시계(`page.clock.install()`) 뒤 새로고침을 거듭하면 framer 애니메이션이 opacity 0에 멈춘다.
- 알게 된 것: 시계 있음/없음 두 번 재현해 원인을 특정. 시계는 필요한 단계에서만, "보임" 검사엔 조상 opacity 1 확인.
- 다음엔: 시각 검증 스크립트의 핵심 검사엔 "사람 눈에 보이는가"(opacity·크기)를 같이 건다.

**3. 개발 기기의 환경이 측정을 오염시킨다 — 로컬 설치 글꼴** (docs/03 M5 측정 4)
- 상황: PNG 글자 방식 비교에서 SVG `<text>`도 화면과 똑같이 나왔다.
- 몰랐던 것: 이 Mac에 Pretendard가 로컬 설치돼 있어, 이미지 안 SVG가 웹폰트 대신 로컬 글꼴을 찾은 것.
- 알게 된 것: 로컬 이름을 뺀 재현(`svg-fallback`)에서 대체 글꼴로 떨어짐. canvas 방식도 로컬 이름을 빼고 재측정해 웹폰트 사용을 확인.
- 다음엔: "여기선 된다"는 결과는 사용자 기기와 다른 점(글꼴·포트·저장소)을 먼저 나열하고 그걸 빼고 다시 잰다.

**4. 색은 대비만이 아니라 서로의 구분도 재야 한다** (docs/03 M3 팔레트 표)
- 상황: 과목 5색 첫 후보는 대비는 괜찮았다.
- 몰랐던 것: 적록색약 시뮬레이션에서 수국(파랑)·라벤더가 ΔE 2.5로 겹쳤다.
- 알게 된 것: WCAG 대비 + 색끼리 ΔE + 색약 시뮬 ΔE 세 축으로 후보 3개를 비교해 골랐다. 라이트 해바라기는 대비 2.17로 기준 미달 — 진한 중심으로 형태 보완, 한계로 기록.
- 다음엔: 범주형 색이 필요하면 측정 스크립트(`scratchpad/palette.mjs` 방식)를 먼저 돌리고 시안을 만든다.

**5. Node 24 타입 제거 테스트는 import 규칙을 바꾼다** (docs/03 테스트 정책, `54696c8`)
- 상황: `node --test`로 TS를 바로 돌리려 했다.
- 몰랐던 것: 확장자 없는 런타임 import는 `ERR_MODULE_NOT_FOUND`, 확장자를 붙이면 tsc가 TS5097.
- 알게 된 것: 테스트 대상 모듈은 `import type`만 허용(자급) + `allowImportingTsExtensions`. 디렉터리 인자 대신 glob.
- 다음엔: 새 프로젝트 템플릿에 이 테스트 설정을 기본으로 넣는다 (아래 환류 제안).

**6. 데모 시드가 제품의 한계를 드러냈다** (M6 README 스크린샷)
- 상황: README용으로 "하루 1시간 이상 공부한 달"을 시드했더니 과목 꽃색이 거의 안 보였다.
- 몰랐던 것: 식물은 심은 뒤 540분 누적이면 나무가 되는데, 나무는 과목 표시가 없다 — 꾸준히 공부할수록 과목 분포가 안 보인다.
- 알게 된 것: 26시간 달 기준 28그루 중 과목 꽃 4~5송이(실측). 측정 계획 2(나무 단계 표현)가 생각보다 중요하다.
- 다음엔: 스크린샷용 시드와 별개로 "실사용에 가까운 시드"로 한 번은 찍어 본다.
- 후속: 사용자 피드백("비실비실")과 합쳐 아트 개정 B — 나무 수관에 과목색 꽃을 피워 해결 (2026-11-25 확정).
