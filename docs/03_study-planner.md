# 03 — 공부 계획 고도화 (목표 체크리스트 · 과목 식물 · D-day · 월간 정리)

> 상태: **승인 (2026-11-25) · M1~M5 완료 (측정 2는 아트 개정 B로 해소) · M6 진행 — 배포(main 푸시) 승인 대기**

## 배경

개발 공모전 제출을 위해 V1 유지보수 모드를 이 문서 범위에 한해 해제한다.
현재 앱은 *얼마나* 공부했는지(세션 시간)만 알고 *무엇을* 했는지는 모른다.
학생에게 실제로 도움이 되는 건 "오늘 할 일을 정하고 → 집중해서 하고 → 돌아보는"
루프이므로, 이 루프를 정원 은유 안에서 완성한다:

**할 일(과목 태그) → 집중 세션 → 과목별 식물이 자람 → 핵심 목표를 다 하면 달성 꽃 →
월말에 한 달의 정원을 정리 카드로 돌아봄.** 시험 D-day는 이 루프의 동기(왜 오늘
공부하나)를 홈에 한 줄로 보여준다.

## 목표 / 비목표

**목표**

1. **오늘의 목표 체크리스트** — 그날의 할 일을 적고 체크한다. 그중 1~3개를
   **핵심 목표**로 지정하고, **핵심 목표를 모두 완료한 날에는 정원에 달성 꽃이
   하나 더 핀다.**
   - 세션 식물(세션 1회 = 식물 1그루)은 **그대로 유지**한다. 달성 꽃은 추가 보상이며,
     달성하지 못해도 잃는 것은 없다.
2. **과목 태그 → 과목별 식물 종** — 과목을 최대 5개 등록하고 각 과목에 식물 종을
   하나씩 배정한다. 세션 시작 시 과목(또는 할 일)을 고르면 그 세션의 식물이 해당 종으로
   자란다. 정원만 봐도 이 달의 과목 분포가 보인다.
3. **시험 D-day** — 시험 이름과 날짜를 등록하면 홈에 가장 가까운 시험까지
   **남은 날만** 한 줄로 표시한다.
4. **월간 정원 정리 카드** — 기록 페이지에서 한 달을 돌아보는 카드
   (그달 정원 + 총 시간 + 과목 비율 + 달성 꽃 수)를 보여주고 **PNG로 저장·공유**한다.

**비목표** (범위 확장은 여기서 막는다)

- 백엔드·계정·기기 간 동기화·친구 정원 없음 (데이터는 계속 localStorage).
- 알림·리마인더 없음 (제품 원칙).
- 반복 할 일, 마감일 있는 할 일, 장기 플래너/캘린더형 일정 관리 없음 — 할 일은
  **"오늘"에만** 속한다.
- D-day의 역산 계획(주간 목표 시간 자동 계산) 없음 — 남은 날 표시만.
- 주간 리포트 없음 — 정리 카드는 월 단위만.
- 달성하지 못한 날의 페널티(시드는 식물, 경고 문구) 없음.
- 기존 세션 기록에 과목을 소급 지정하는 UI 없음 (기존 식물은 지금 모습 유지).

## 계약

### 데이터 모델 (모두 하위 호환 — 기존 데이터 마이그레이션 없음)

```ts
// types/index.ts — 기존 Session에 선택 필드 추가
interface Session {
  id: string
  completedAt: string
  durationMin: number
  subjectId?: string   // 신규: 없으면 지금과 동일한 식물(기존 동작)
  taskId?: string      // 신규: 이 세션이 어떤 할 일을 위한 것이었는지
}

interface Subject {
  id: string
  name: string         // 예: "수학"
  species: SpeciesId   // 0..4 — 과목마다 고유, 중복 배정 불가
  archived?: boolean   // 삭제 대신 보관: 과거 세션의 식물 종이 바뀌지 않게
}

interface Task {
  id: string
  date: string         // 로컬 기준 'YYYY-MM-DD' — 할 일이 속한 날
  title: string
  subjectId?: string
  core: boolean        // 핵심 목표 여부 (하루 최대 3개)
  done: boolean
  doneAt?: string      // ISO
  createdAt: string    // ISO — 목록 정렬용
  carriedFrom?: string // "어제 남은 할 일 가져오기"로 복사된 경우 원본 id (중복 방지)
}

interface Exam {
  id: string
  name: string         // 예: "기말고사"
  date: string         // 'YYYY-MM-DD'
}
```

### localStorage 키 (신규 3개, 기존 키 변경 없음)

| 키 | 값 |
|---|---|
| `study-garden:subjects` | `Subject[]` |
| `study-garden:tasks` | `Task[]` |
| `study-garden:exams` | `Exam[]` (최대 3개) |

- 읽기는 기존 규칙대로 각 store의 `hydrate()`에서만. 저장소 접근은 `lib/storage/`에
  repository를 추가해 감싼다 (기존 `SessionRepository` 패턴).
- 기존 계약과의 충돌: 없음. docs/01(계절)·docs/02(PWA)와 독립.

### 규칙 (순수 함수 — `lib/`)

- **달성 판정** `isDayAchieved(tasks, date)`: 그날 핵심 목표가 **1개 이상 있고
  전부 done**이면 true.
- **과거 날짜는 읽기 전용**: 날짜가 지난 할 일은 수정·체크·핵심 지정 변경 불가.
  (나중에 체크해서 달성 꽃을 만드는 것을 막고, 판정이 안정적으로 유지된다.)
- **달성 꽃 배치** `getGoalFlowers(tasks, year, month)`: 그달 달성한 날마다 꽃 1송이.
  위치는 기존 식물처럼 데이터에서 결정적으로 유도한다 (`hashCode(date)` — 하이드레이션 안전).
  정원 **앞줄 화단 영역**에 배치해 세션 식물과 구분되게 한다.
- **식물 종** `species`는 세션의 `subjectId` → `Subject.species`로 결정.
  과목이 없거나 보관된 과목을 찾을 수 없으면 기존 동작(variant 기반)으로 그린다.
- **D-day**: 오늘 이후 시험 중 가장 가까운 1개를 "기말고사까지 12일" 형식으로 표시.
  당일은 "오늘은 기말고사 날이에요". 지난 시험은 자동으로 숨긴다(데이터는 유지).

### 화면 변경

| 위치 | 변경 |
|---|---|
| 홈 `/` | 타이머 아래 **"오늘의 목표" 카드**(접힘 기본: "핵심 목표 2/3" 한 줄 + 진행 점). 펼치면 체크리스트. 정원 위 문구 줄에 D-day 한 줄. **정원·타이머가 주인공인 위계는 유지** |
| 타이머 시작 전 | "이번엔 무엇을 가꿀까요?" — 오늘 할 일 칩 / 과목 칩 선택(선택 안 해도 시작 가능) |
| 세션 완료 오버레이 | 연결된 할 일이 있으면 "이 할 일을 마쳤나요?" 체크 버튼 하나 |
| 달성 순간 | 마지막 핵심 목표 체크 시 정원 화단에 꽃이 한 번 피는 framer-motion 등장 + "오늘의 목표를 모두 가꿨어요" (1회, 잔잔하게) |
| 설정 시트 | "과목" 섹션(추가·이름 변경·보관, 종 미리보기) · "시험" 섹션(최대 3개) |
| 기록 `/records` | 캘린더에 달성한 날 작은 꽃 표시 · 하단에 **월간 정원 정리 카드** + "이미지로 저장" 버튼 |

### 월간 정리 카드 이미지 내보내기

- **새 라이브러리 없이** 구현한다: 정원이 이미 SVG이므로 카드 전체를 SVG로 조립 →
  CSS 변수를 `getComputedStyle`로 실제 색값으로 치환 → `<canvas>`에 그려 PNG.
  공유는 Web Share API(파일 공유 지원 시), 아니면 다운로드.
- 무한 애니메이션(흔들림·입자)은 이미지에서 정지 상태로 고정.
- 현재 계절·라이트/다크 테마가 그대로 반영된다.

### 디자인 토큰

- 과목 식물 종은 **형태(꽃잎 모양·잎 배치)로 구분**하고 색은 기존 팔레트 변수
  (`--petal --petal-2 --accent --core --leaf`)를 조합한다. 이걸로 구분이 안 되면
  그때 `--species-1..5`를 라이트 4계절 + 다크 4계절 = 8조합 모두에 추가한다
  (측정 계획 1 결과로 결정).
- 달성 꽃·체크박스·D-day도 기존 토큰만 쓴다. 하드코딩 금지 규칙 그대로.

## 마일스톤

한 마일스톤 = 한 번의 승인 게이트. 각 마일스톤 완료 시 `npx next build` 통과 +
변경 화면 라이트/다크 스크린샷(run-study-garden 스킬)을 보고에 붙인다.

- **M1 — 오늘의 목표 체크리스트 (데이터 + 홈 카드)**: Task 모델·repository·store,
  홈 카드(추가·체크·핵심 지정·삭제), 어제 남은 할 일 가져오기, 과거 날짜 읽기 전용, `isDayAchieved` +
  단위 테스트.
  완료 기준: 판정 골든 케이스 테스트 통과 · 홈 모바일(390px) 스크린샷에서 타이머가
  첫 화면 안에 남음 · 새로고침 후 유지.
- **M2 — 달성 꽃**: `getGoalFlowers`, 정원 화단 렌더, 달성 순간 연출, 기록 캘린더
  꽃 표시. 꽃 일러스트 시안은 사람 검수.
  완료 기준: 시드 데이터로 달성일 N개 → 정원에 꽃 N송이(4계절 × 라이트/다크
  스크린샷) · reduced-motion에서 연출 꺼짐.
- **M3 — 과목과 식물 종**: Subject 모델, 설정 시트 과목 섹션, 타이머 시작 전 선택 UI,
  Session에 subjectId/taskId 저장, 세션 완료 오버레이의 할 일 체크, 식물 종 5개 × 4단계
  일러스트.
  완료 기준: 종 시안 사용자 승인(측정 계획 1) · 과목별 세션 시드 → 정원에서 종이
  구분됨 스크린샷 · 과목 없는 기존 세션은 이전과 픽셀 단위로 같은 모습.
- **M4 — 시험 D-day**: Exam 모델, 설정 시트 시험 섹션, 홈 한 줄.
  완료 기준: 날짜 경계 케이스(당일·내일·지난 시험·시험 없음) 테스트 통과 + 홈 스크린샷.
- **M5 — 월간 정원 정리 카드 + PNG 내보내기**: 기록 페이지 카드, SVG→canvas 내보내기,
  공유/다운로드.
  완료 기준: macOS Chrome·Safari에서 내보낸 PNG 실물 첨부(라이트/다크 각 1장) ·
  측정 계획 4 통과.
- **M6 — 공모전 마감 정리**: 배포(main 푸시는 사용자 승인), README 기능 소개·
  스크린샷 갱신, 공모전 제출용 소개 자료(project-review 스킬).
  완료 기준: 배포판에서 M1~M5 시나리오 한 바퀴 실행 기록 · 기존 실사용 데이터가
  그대로 보임.

## 측정 계획

1. **식물 종 구분성**: 5종 × 4단계를 실제 정원 축척(depth 0/0.5/1)으로 렌더한 비교표를
   8조합(4계절 × 라이트/다크) 스크린샷으로 만들어 보여준다. "형태만으로 구분되는가"를
   사용자가 판정하고, 안 되면 색 토큰 추가로 간다.
2. **나무 단계의 종 표현**: 식물은 심은 뒤 540분 누적이면 나무가 된다. 나무 단계에서도
   종을 구분할지(예: 꽃이 핀 나무) 결정하기 위해, **실사용 데이터 export**(배포판에서
   `study-garden:sessions` 복사)로 이 달 식물의 단계 분포를 계산해 나무 비율을 먼저 본다.
   비율이 낮으면 나무는 기존 3수종 유지.
3. **홈 밀도**: 체크리스트 카드 접힘/펼침 × 할 일 0·3·8개 상태를 390px·1280px로 찍어,
   타이머 시작 버튼이 첫 화면 안에 있는지 확인한다. 기본 접힘 여부는 이 스크린샷으로
   사용자가 결정한다.
4. **PNG 내보내기 품질**: SVG를 이미지로 그리면 외부 폰트(Pretendard CDN)가 적용되지
   않는다. ① SVG 안 텍스트 ② canvas `fillText`(document.fonts 로드 후) 두 방식으로
   같은 카드를 뽑아 비교하고 사용자가 고른다.

## 테스트 · 골든 케이스

- 새 라이브러리 없이 **Node 24 내장 `node --test`**(TS 타입 제거 내장)로 `lib/`
  순수 함수를 테스트한다. 대상: `isDayAchieved`, 과거 날짜 잠금, `getGoalFlowers`
  결정성, D-day 계산.
- **골든 케이스는 사람이 검수한다**: 케이스 표(입력 → 기대값) 초안을 먼저 보여주고
  승인받은 뒤 테스트 파일을 쓴다. 구현 코드가 기대값을 스스로 만들지 않는다.
- **실측 (2026-11-25, Node 24.18)**: `import type { X } from '@/types'`는 타입 제거로
  지워지므로 `node --test`에서 문제없다. 그러나 **확장자 없는 런타임 import
  (`from './time'`)는 `ERR_MODULE_NOT_FOUND`로 실패**한다 (`lib/stats.ts` 로드로 재현).
  → 정책: 테스트 대상 신규 모듈(`lib/tasks.ts`, `lib/dday.ts`)은 **런타임 import 없이
  자급**한다(`import type`만 허용).
- **테스트 파일 쪽은 `./tasks.ts`처럼 확장자를 붙여야** Node가 실행하는데, 그러면
  tsc가 TS5097을 낸다(실측). → tsconfig에 `allowImportingTsExtensions: true` 추가
  (2026-11-25 사용자 승인, noEmit이라 허용됨). 초안의 "tsconfig 변경 없음"을 대체한다.
- `npm test` = `TZ=Asia/Seoul node --test 'lib/**/*.test.ts'`. 디렉터리 인자(`node --test lib/`)는
  Node 24에서 디렉터리를 파일로 실행하려다 실패한다(실측) — glob을 쓴다. TZ 고정은 A3용.

## 알려진 리스크 / 한계

- **자기 신고 체크**: 체크는 본인이 누르는 것이라 속일 수 있다. 핵심 목표 3개 상한과
  과거 날짜 잠금으로 "쉬운 항목을 많이 적는" 우회는 막지만, 완전히 막지는 못한다.
  → 다음 단계 영향: 공모전 발표에서 "자기 관리 도구이므로 신뢰 기반" 논리로 설명.
- **자정 경계**: 밤 11시 50분에 시작한 세션이나, 자정을 넘겨 체크한 할 일이 어느 날에
